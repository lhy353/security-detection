# 会议任务审计工具 — 索引

本文件提供能力边界、路由规则与使用约束。详细说明见 `references/`，实际执行在 `scripts/`。

**当前版本**: 0.2.2

## 能力概览

| 模块 | 核心能力 |
|------|---------|
| `audit` | 任务审计全流程：输入任务要求 → TPR式多轮提问 → 收集信息 → 输出结构化审计报告 |

## 统一规范

- **鉴权依赖**：`cms-auth-skills/SKILL.md`（本 skill 本身不调用外部 API，无需鉴权）
- **运行日志**：`.cms-log/`
- **执行模式**：纯对话引导，无需脚本执行；最终报告由 AI 根据对话内容整理生成

## 授权依赖

本 skill 为纯对话型工具，不涉及外部 API 调用，无需鉴权。

## 输入完整性规则

用户必须提供：
1. **任务要求**：具体要审计的任务内容（可以是会议纪要、行动项列表、邮件等）
2. **被审计方**：责任人或团队名称

缺少上述两项时，不得进入审计流程。

## 建议工作流

```
Step 1  读取任务要求，明确审计范围和目标，建立会话内追踪表
Step 2  进入 TPR 核查流程，逐议题提问 + 实时更新追踪表（不输出中间小结）
Step 3  追问直到信息充分或用户表示"只能这样了"
Step 4  收集完毕后，输出完整结构化审计报告（Stage 3）
Step 5  用户确认"没有补充"后，**必须完成工作计划确认**（Stage 4）
Step 6  工作计划确认完毕，输出最终确认版工作计划
```

**关键原则：Stage 4（工作计划确认）不可跳过。** 即使用户说"生成报告"，也必须先完成工作计划确认步骤。

## 审计报告结构

```
一、整体审计结论（表格）
二、分议题详细核查（每议题末尾直接带下一步工作计划）
三、待办事项汇总（从各议题提取，表格形式）
四、新发现问题汇总
五、后续跟进机制
```

## 宪章

1. **记录结论 + 简单评价**：每项议题记录做到了什么、没做到什么，末尾加一句主观评价（做得怎么样、有没有做完、问题在哪）
2. **追问原则**：答非所问或信息不全时必须继续追问，直到搞清楚或用户明确表示"只能这样了"
3. **计划嵌入议题**：每项议题末尾直接带下一步工作计划，结尾再出一份汇总表
4. **工作计划确认**：Stage 4逐项确认每条工作计划，确保责任人和时间已明确
5. **会话内追踪**：每个议题完成后实时更新内部追踪表，保证连贯性，避免重复输出
